# Marrow input-behaviour prototype

A small, offline prototype for the Marrow condition: decide whether the person
at the computer is the enrolled user from ordinary pointer, click and text
events, with fake data only.

The repository includes:

- an operating-system-neutral JSONL recording format;
- scale-free pointer/text feature extraction;
- a per-user verifier trained from enrolment recordings;
- a deterministic fake-data generator with two input styles and held-out tired
  owner, stranger and mimic recordings;
- a swap test and held-out false-accept / false-reject report;
- a one-command demo and a generic train/score command line.

There is no capture software, no network call, no camera, no audio, no real
movement data and no third-party Python dependency.

## Quick start

```sh
python3 run_demo.py
```

This writes `data/synthetic.jsonl` and the reports under `reports/`. It is
deterministic for seed `1883`.

## How it works

1. **Events.** A recording is a list of millisecond timestamps and events:
   pointer moves with `x`/`y` as fractions of the screen, clicks, and text
   events with `source` = `typed`, `onscreen` or `dictation`. Deletions are
   `"\b"` text events. Extra capture metadata is ignored.
2. **Features.** 21 scale-free features describe pointer speed/acceleration,
   pause structure, direction change and path geometry; click rate and timing;
   text rate, interval rhythm, bursts, corrections and source mix. No pixel
   coordinates, window size, OS, application or device identity is used.
3. **Profile.** For each enrolled person, a logistic verifier is trained with
   that person's enrolment recordings as positives and the other enrolled
   people's enrolment recordings as background negatives. Features are
   normalised by a robust reference centre/scale from enrolment only.
4. **Decision rule.** A recording is accepted only when the claimed profile's
   score is at least **0.90** and at least **0.20** above the best other
   same-style profile. The relative term is an open-set identification margin:
   the claimed profile must be the best match, not just over a global line.
   With one enrolled profile the relative term is skipped. See
   [`THRESHOLD.md`](THRESHOLD.md); the rule was fixed before held-out scoring.
5. **Swap test.** For every profile B, every genuine owner recording of another
   person A in the same style is scored against B. B must reject A. The demo
   gets 0 accepted swaps out of 120 attempts.

## Recording format

UTF-8 JSON Lines, one session per line:

```json
{"session_id":"demo-1","subject_id":"alice","input_style":"mouse_keyboard","role":"owner","tired":false,"events":[{"t":0,"type":"move","x":0.12,"y":0.44},{"t":19,"type":"click","x":0.12,"y":0.44,"button":"left"},{"t":50,"type":"text","text":"h","source":"typed"},{"t":73,"type":"text","text":"\b","source":"typed"},{"t":91,"type":"text","text":"hello","source":"dictation"}]}
```

Required event fields:

| Event | Required fields |
|---|---|
| `move` | `t`, `type`, `x`, `y` |
| `click` | `t`, `type`, `x`, `y`; optional `button`, `duration_ms` |
| `text` | `t`, `type`, `text`, `source` |

`x` and `y` must be fractions in `[0, 1]`. `t` is milliseconds and may use any
origin; only differences are used. `source` is exactly `typed`, `onscreen` or
`dictation`. A deletion is a text event with `text` equal to `"\b"`. Session
labels (`role`, `tired`, `split`) are optional for scoring unlabelled data.

The loader validates shape, ranges and event ordering. A recording can include
arbitrary extra metadata; it is ignored by feature extraction.

## Generic commands

Generate the fake dataset:

```sh
python3 -m marrow.cli generate --out data/synthetic.jsonl
```

Print features for any recording in the format:

```sh
python3 -m marrow.cli features --recordings data/synthetic.jsonl
```

Train one profile. The enrolment file may contain several subjects, in which
case the other subjects are used as background negatives; or pass a separate
background file:

```sh
python3 -m marrow.cli train \
  --subject-id alice \
  --enrol alice-enrolment.jsonl \
  --background background-recordings.jsonl \
  --out alice-model.json
```

Score new recordings against that model:

```sh
python3 -m marrow.cli score \
  --model alice-model.json \
  --recordings new-recordings.jsonl
```

Run the labelled held-out evaluation and swap test:

```sh
python3 -m marrow.cli evaluate --recordings data/synthetic.jsonl
```

      millisecond timestamps, fractional pointer positions, clicks, and text
      labelled by arrival path; includes an offline train/test script.

## Limitations

This is a **fake-data prototype**, not a claim of real-world biometric accuracy.
The synthetic generator is deliberately small and respectful of privacy: it
proves the interface, feature path, offline evaluation and swap-test protocol,
not that the same rates will hold on real users. A real deployment needs more
enrolment sessions per person, broader device/input coverage, a pre-registered
evaluation protocol and external validation. The conservative rule rejects some
genuine owner sessions (10% here); the threshold is exposed as a policy choice
and should be set by the operator before deployment, not tuned on the final test
set. No private key, wallet, account or capture software is used or requested.
